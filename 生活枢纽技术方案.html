生活枢纽 · 技术方案

个人生活管理 Web 应用　|　v0.1　|　自托管 · 数据归你

项目定位：一个完全运行在你自己服务器上的个人生活管理站。包含 作息 / 饮食 / 学习 / 日记 四大模块，并内置一个 AI 助手，能基于你的记录生成周报、营养分析、学习报告与情绪洞察。核心原则是数据自托管——没有任何记录落到第三方云。

一、技术选型

考虑点：个人使用（单用户、低并发）、要自托管、要易维护易备份、AI 要能接。我的建议是用 Next.js 做全栈，前后端同一套代码、一次部署，最省心。

层选型理由
前端框架Next.js 14 (App Router) + React + TypeScript你给的 HTML 设计语言（CSS 变量、卡片网格、衬线标题）可直接复用；SSR 对自托管友好
样式Tailwind CSS把现有设计 token（--accent-routine 等）转成 theme，一致性拉满
图表Recharts趋势图 / 时间线 / 环形图，React 生态最稳
富文本Tiptap日记模块的富文本 + 心情标记
后端Next.js Route Handlers (app/api/**)不另起服务，和前端同仓同部署
数据库SQLite + Prisma单文件、零运维、备份 = 复制一个文件；Prisma 让表结构清晰
鉴权单密码会话 (cookie)个人站不需要多用户，一个密码进门即可
AILLM API（可切换）OpenAI 兼容 / DeepSeek / 本地 Ollama，见第七节
部署Docker Compose一条命令跑起前后端 + 数据库，自有 VPS 即可
备选：若你日后想上 Postgres（多端同步、并发写入更稳），Prisma 换一个 datasource 即可，业务代码几乎不动。

所有读写都走你自己的 Next.js + SQLite，没有任何数据默认上传到第三方。AI 那一路是可选的、可开关的，且能指向本地模型做到完全离线。

三、数据模型（Prisma 草案）

// 作息：每天一条睡眠记录 model Routine { id Int @id @default(autoincrement()) date DateTime @db.Date // 哪一天 wakeAt DateTime? // 起床时间 sleepAt DateTime? // 入睡时间 quality Int? @default(3) // 睡眠质量 1-5 note String? } // 饮食：每餐一条 model Meal { id Int @id @default(autoincrement()) date DateTime @db.Date type String // breakfast/lunch/dinner/snack content String // 吃了什么 calories Int? // 热量(可选) note String? imageUrl String? // 食物图(可选) } // 学习：目标 → 任务 → 番茄钟 model StudyGoal { id Int @id @default(autoincrement()) title String category String? // 科目/项目 tasks StudyTask[] } model StudyTask { id Int @id @default(autoincrement()) goalId Int title String done Boolean @default(false) pomodoros Int @default(0) // 完成的番茄数 } model Pomodoro { id Int @id @default(autoincrement()) taskId Int? startedAt DateTime duration Int // 分钟 } // 日记：每天一篇 model Journal { id Int @id @default(autoincrement()) date DateTime @db.Date content String // 富文本 HTML/JSON mood String? // 心情标记 }

四、模块拆解

① 概览页（你已有的 HTML）

作为首页 / Dashboard。直接把你的设计稿搬进来，卡片点击进入对应模块。底部保留"数据仅存你自己的服务器"提示。

② 作息管理

  • 表单：日期、起床/入睡时间、睡眠质量滑块、备注
  • 视图：每日时间线 + 近 30 天睡眠时长/质量趋势图（Recharts）
  • API：GET/POST /api/routine、GET /api/routine/trends

③ 饮食记录

  • 表单：日期、餐别、内容、热量、备注、拍照（可选图片上传到本地）
  • 视图：当日三餐列表 + 周度饮食结构回顾
  • API：GET/POST /api/meals、POST /api/meals/upload

④ 学习计划

  • 目标/任务 CRUD，番茄钟计时器（前端计时 + 落库 Pomodoro）
  • 视图：目标进度条、按科目分类、累计专注时长
  • API：/api/study/goals、/api/study/tasks、/api/pomodoro

⑤ 每日日记

  • Tiptap 富文本编辑，心情标记（emoji/标签）
  • 视图：按日期归档的时间线，可检索
  • API：GET/POST/PUT /api/journal

⑥ AI 助手（复用你那颗可拖拽悬浮球）

  • 面板里 6 个预设：周报总结 / 营养分析 / 学习报告 / 情绪洞察 / 改善建议 / 自由问答
  • 后端把对应模块的数据组装成 prompt，调用 LLM，流式返回
  • API：POST /api/ai/chat（服务端持 key，数据不出服务端）

六、部署（自托管）

  • Docker Compose：一个 next 服务 + 挂载的数据卷（SQLite 文件 + 上传图片）。
  • 运行环境：任意 VPS、群晖、甚至家里一台常开机器；端口反代 + HTTPS（如 Caddy）。
  • 备份：SQLite 是单文件，定时 cp 即可；可加 cron 每日打包。
  • 环境变量：SITE_PASSWORD（进门密码）、LLM_API_KEY / LLM_BASE_URL / LLM_MODEL（AI 用）。

七、待你确认（决定后就开干）

① AI 用哪家？

  • 云端 API 如 DeepSeek / 通义 / OpenAI 兼容（效果最好，但记录会发给模型）
  • 本地模型 如 Ollama + Qwen（完全离线、最隐私，但需要机器有算力）

② 要不要进门密码？

  • 个人站建议加一个简单密码，防被扫到。

③ 部署到哪？

  • 已有 VPS / 群晖？还是先在本地 npm run dev 跑起来看效果？

④ 饮食要拍照吗？

  • 要的话需要图片上传 + 本地存储，会多一小块工作。
